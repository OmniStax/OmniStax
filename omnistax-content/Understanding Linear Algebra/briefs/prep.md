# Prep: one chapter, before its sections are built in parallel

You own `$BOOK/chNN/` except the section folders' `plan.md`, `text.html`, `figures.js`, `section.json`, and `book.json` only through `ost merge`. The previous chapter is already merged (its concept ids are in `book.json`: `ost rows understanding-linear-algebra concepts --chapter <N-1>`), so your prerequisite edges may point into it.

1. Read every `source.md` of the chapter (`chNN/N.M/source.md`, and `chNN/intro/source.md` where the chapter has an introduction). Skim the chapter in the PDF for what the printed page looks like.
2. `chNN/exploration.md`: module table with counts (preview activities, activities, examples, definitions, theorems and propositions, observations, figures by kind, tables, Sage cells, interactives, end exercises and how many answered); the exercise count report of root rule 13 counted from the source, with the standing choice (book answers; AI solutions for the unanswered, named); figure numbers in book order with what each draws (PreFigure diagram, photograph, interactive) and whether it sits in running text, an activity statement, an answer, or an exercise; what is new in the chapter; which figures are sketches to replace, which photographs to keep or drop and why; the author's interactives and the 3Blue1Brown survivors (from `$BOOK/exploration.md`) that fall in this chapter; exercises that belong to another section; the chapter's answer to root rule 23.
3. `chNN/config.md` (one line per setting: the standing decisions of `$BOOK/RULES.md` carried over, then the chapter-specific lines: numbering, which figures fold, photographs, interactives, 3D, the exercise count report and its choice; a status line) and `chNN/COLOR.md` (what the chapter colours by each of rule 7's four ways; the referents planned per figure).
4. `chNN/chapter.json`: `id` (the chapter number as a string), `dir`, `title`, `intro: {"module": "chapN-introduction"}` where the book prints one (not Chapter 1), all `sections` (`id`, `module` the xml:id, `title`), then `variables` per section, no anchors. Before each variables row, `ost meanings understanding-linear-algebra <sym>` (rule 19): reuse the earlier meaning for the same quantity; where the book gives the symbol a new one, write it to stand alone and set `redefines`. A symbol key is the plain letter (`v_vec` for **v**, `A`, `lambda`, `x_1`); its `latex` the book's (`\mathbf{v}`). Write the file whole once; correct with `ost set`.
5. `chNN/book-rows.json` then `ost merge understanding-linear-algebra N`: symbols with `\k` macros for typed symbols the text writes (`\kvecv`, `\kA`, `\klambda`; never restage an existing one); concepts per section per root rule 6 (everything the section teaches, tested or not: every italic defined term and every Definition box, every Proposition and Theorem, the ideas and skills; kind definition/axiom/result/idea/skill as the book treats it; canonical ids, reusing Calculus's and Diffy Qs's where they state the same thing (`ost find calculus …`, `ost find diffyqs …`, and the list in `$BOOK/exploration.md`); a terse name with no formula or gloss; statement in the book's voice; `terms`, the book's italic words for it; `symbol`, the one key it is denoted by; `type`, where it names one; `forms`, every equation that states it, the main form first, with ids unique in the book (`eq-…`)); prereq edges, at least the definitions a statement uses, into merged chapters and within the chapter, Hasse-reduced (direct prerequisites only, nothing already reached through another); placeholders only inside the chapter. After the merge, set `concept` on each variables row of `chapter.json` whose symbol names a concept, and only those (`ost set`).
6. The chapter introduction page, where the book prints one: `chNN/intro/text.html`, `figures.js` (empty registration if no figure) and `section.json` (`id` the literal `intro`, `chapter`, `title` the chapter's, empty lead, objectives, summary, exercises and coverage; `notes`, `ai`, `built`), the prose verbatim in one `<section id>` block with `data-concept` spans on the concepts it names; a figure it prints is transformed like a section's. Model it on `omnistax-content/College Physics 2e/ch03/intro/` (its `section.json`, `text.html` and `figures.js`), and follow `docs/content-format.md`'s `chapter_pages`.
7. Checks: `ost check understanding-linear-algebra`, `npm test` in the app, `OMNISTAX_BOOKS=understanding-linear-algebra npm run test:books`.

Report: concept ids per section (id · kind · statement in a few words), symbols added with their macros, form ids, the figure and activity numbers each section uses, anything a section agent must know (a figure held for another section, an exercise held, a referent planned).
