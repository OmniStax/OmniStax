# Generated exercises and AI grading (#9)

Status: built, 2026-10-05.

A round draws from one integrated set. Each item is either from the book or
generated by the reader's own model, and a generated card is the ordinary
exercise card wearing the AI mark ("Generated by <model>"). A reader who wants
the book alone sets Generated to "book only".

## The data

`lib/practice/generated.ts` defines `GeneratedExercise`: `{ id, book, section,
concepts, prompt, answer, bloom, facet, model, created, uses, request }`. The
answer is the book's own `AnswerSchema` union with `generated_by: 'ai'`, and
`section` is the section that introduces the concept, which is where attempts
and scratch pages are filed. The records live in IndexedDB `omnistax-generated`,
store `generated` (`generated-db.ts`), and are held live by `generated.svelte.ts`.
The runner sees each one as an end exercise whose id is `ai:<id>`.
`books.exercise(book, section, id)` resolves both kinds, which is the lookup the
store uses for a drawn item.

Availability for mastery counts book items and, while generated items are
included, the stored generated items for that concept. Mastery stays at "three
until mastered". Wrong answers still subtract a step, and mastery stays sticky.

## The flow

On the Choose face, each eligible concept gets a row under the picked list with
its book count and an editable "wanted" count. A stepper sets the round's default.
Both are kept on the page as `round`, not in settings.
`quotaOf` (model.ts) gives `{ wanted, book, gap }`. Book only caps the wish at
the book, so it never shows a gap. `prepare` takes the round and the extra items
and reports each concept's quota.

Start fills the gaps (`fillGaps` in `ai.svelte.ts`). It reuses stored items for
the concept first, least used first, and skips items already answered right
unless nothing else is left. "Generate new, don't reuse" turns reuse off. It
generates the rest three concepts at a time, at most six items per request,
with a progress line. Then `prepare` runs again with the extras and the round
starts. A concept that cannot be written for keeps its book items, and a
one-line notice says so. Drawing an item adds one to its `uses`.

## The prompts

`prompt.ts` holds both prompts. The generation prompt carries the pedagogy:
read the section first, enumerate the concept's facets before multiplying
items, cover uncovered facets first, write one of three kinds of item
(numeric with value, unit and tol; multiple choice whose distractors each encode
a real confusion; open with a model solution), name each item's facet and Bloom
level, and answer with one fenced json array. The request names the book,
section and concept with its statement, the reader's optional note, the book's
own prompts for the concept, the count, and the facets stored items already
cover. `generate.ts` runs `read_section`, `lookup` and `search` through
`runTool` for up to six rounds, then parses the json with zod. It keeps every
good item, names each bad item, and retries once with the parser's errors when
no item is readable.

AI grading (`grade.ts`) sends the exercise, the reference answer and solution,
the reader's text and, when attached, the scratchpad rasterised at 1000 px wide
(`thumbnailOf(id, ink, { width })`). It reads `{ verdict, feedback }`. A "right"
verdict records a correct attempt. "Partial" and "wrong" record an incorrect
one. If the call fails, the item goes back to Reveal and check. Multiple choice
is still checked by the app.

## What is stored and exported

Settings gain `generated`, `grading`, `promptNote`, `fresh` and `model` (the one
pick for generation and grading, from the same menu Ask AI uses). A finished
session is kept with `status: 'done'` and `ended`. Past sessions lists these
sessions with Open, a read-only replay, and Delete. A backup carries
`generated: GeneratedExercise[]` beside the chats, and the settings, pages and
sessions keys stay in the Practice category. Deleting a generated item keeps its
attempts.

## Deliberately not done

- Generated items are not added to the book or shared between readers, and no
  agent reviews them before a reader sees them.
- There is no JSON mode or structured-output API. The fence plus zod works with
  every provider.
- The git sync layout (`lib/sync/layout.ts`) does not write `generated` as files
  yet, so a sync round-trip drops them. A file backup keeps them.
- A section pick does not bring in a concept whose section has no exercise. Add
  that concept by name.
